▶️  PREREQUISITES
────────────────────────────────────────────────────────────────────────────

Before starting, ensure you have:

1. Docker & Docker Compose installed
   $ docker --version
   $ docker-compose --version

2. PostgreSQL container running (mcp-postgres)
   $ cd ../DockerConfig && docker-compose up -d

   Verify container is running:
   $ docker ps | grep mcp-postgres

   Expected: Container should show as "Up" on port 5434

3. Environment variables configured
   $ cp .env.example .env

   Edit .env and verify:
   - DATABASE_URL=postgresql://mcp_user:password@localhost:5434/mcpdb
   - GOOGLE_API_KEY=your-gemini-api-key (optional, needed only for embeddings)
   - SCHEMA_NAME=test
   - BATCH_SIZE=8

4. PostgreSQL connectivity
   $ docker exec mcp-postgres psql -U mcp_user -d mcpdb -c "SELECT 1;"

   Expected output: single row with "1"

▶️  TROUBLESHOOTING
────────────────────────────────────────────────────────────────────────────

SCHEMA_NAME Configuration Issues:

Problem: "Schema name not recognized" or "Schema 'test' not found"
Solution:
  1. Verify SCHEMA_NAME is set in .env:
     $ cat .env | grep SCHEMA_NAME
     Expected: SCHEMA_NAME=test (or your configured value)

  2. If missing or wrong, edit .env:
     $ vi .env
     # Find line: SCHEMA_NAME=test
     # Ensure no spaces around = sign

  3. Verify deploy.sh reads it correctly:
     $ grep -A 2 "source.*ENV_FILE" ./scripts/deploy.sh
     # Should show .env loading

  4. Re-run deployment with correct schema:
     $ ./scripts/deploy.sh

Problem: "Schema exists but tables not found"
Solution:
  1. Verify correct schema name:
     $ docker exec mcp-postgres psql -U mcp_user -d mcpdb -c \
       "SELECT schemaname FROM pg_namespace WHERE schemaname LIKE '%test%';"

  2. If different schema created, check .env history:
     $ git log -p -- .env | grep SCHEMA_NAME

  3. Deploy to correct schema:
     $ vi .env  # Set SCHEMA_NAME to matching value
     $ ./scripts/deploy.sh

Problem: "Multiple schemas created" (test, dev, prod all exist)
Solution:
  All schemas can coexist. To clean up old schemas:
  $ docker exec mcp-postgres psql -U mcp_user -d mcpdb -c \
    "DROP SCHEMA IF EXISTS old_schema CASCADE;"

  Then set SCHEMA_NAME in .env to desired schema and redeploy.

────────────────────────────────────────────────────────────────────────────

General Deployment Issues:

Problem: "Container 'mcp-postgres' not found"
Solution:
  $ cd ../DockerConfig
  $ docker-compose up -d
  $ docker ps | grep mcp-postgres

Problem: "Cannot connect to database"
Solution:
  Check database is accepting connections:
  $ docker exec mcp-postgres psql -U mcp_user -d mcpdb -c "SELECT 1;"

  If failed, check PostgreSQL logs:
  $ docker logs mcp-postgres | tail -50

Problem: "File not found: deploy.sql"
Solution:
  Ensure you're in the SQL directory:
  $ pwd  # Should show: /path/to/Lab01-MCP/SQL
  $ ls 05_orchestration/01_deploy.sql  # Should list the file

Problem: "Permission denied" when running scripts
Solution:
  Make scripts executable:
  $ chmod +x ./scripts/deploy.sh
  $ chmod +x ./scripts/verify.sh

Problem: "Google API key not found" (embeddings fail)
Solution:
  Embeddings are optional. To enable:
  1. Get API key from Google AI Studio (ai.google.dev)
  2. Add to .env file: GOOGLE_API_KEY=your-key-here

  Or skip embeddings:
  $ python3 src/populate.py --db --table service_types

Problem: Deployment fails midway
Solution:
  1. Check error message in output
  2. Run validation to identify issue:
     $ ./scripts/deploy.sh --validate-only
  3. Check database logs:
     $ docker logs mcp-postgres | tail -100
  4. If issue found, fix, then re-run:
     $ ./scripts/deploy.sh

Problem: "Extension 'vector' does not exist"
Solution:
  pgvector must be installed in PostgreSQL:
  $ docker exec mcp-postgres psql -U mcp_user -d mcpdb \
    -c "CREATE EXTENSION IF NOT EXISTS vector;"

Problem: Out of memory during embeddings
Solution:
  Reduce batch size in .env:
  BATCH_SIZE=4  # Default is 8

  Then retry:
  $ python3 src/populate.py --db --table products

▶️  DEPLOYMENT CONFIGURATION
────────────────────────────────────────────────────────────────────────────

Environment variables (.env file):

DATABASE_URL
  Format: postgresql://user:pass@host:port/database
  Example: postgresql://mcp_user:password@localhost:5434/mcpdb
  Required: Yes

GOOGLE_API_KEY
  For: Generating product embeddings
  Source: https://ai.google.dev/
  Required: Only for product embeddings

SCHEMA_NAME
  Value: test (default)
  Purpose: PostgreSQL schema name (dynamic, read from .env)
  Required: Yes

  IMPORTANT: All SQL deployment scripts use this variable!
  - Schema creation uses: CREATE SCHEMA :SCHEMA_NAME
  - Table creation uses: CREATE TABLE :SCHEMA_NAME.table_name
  - All indexes use: ON :SCHEMA_NAME.table_name
  - All functions use: CREATE FUNCTION :SCHEMA_NAME.function_name

  Multi-Environment Support:
  - Development: SCHEMA_NAME=dev
  - Testing: SCHEMA_NAME=test
  - Staging: SCHEMA_NAME=staging
  - Production: SCHEMA_NAME=prod
  - Custom: SCHEMA_NAME=my_schema

  How It Works:
  1. Shell scripts (deploy.sh, verify.sh) read .env
  2. SCHEMA_NAME value passed to psql with -v flag
  3. SQL files reference variable as :SCHEMA_NAME
  4. PostgreSQL substitutes actual schema name at runtime

  Change Log Example:
  $ vi .env                    # Edit SCHEMA_NAME=test to SCHEMA_NAME=production
  $ ./scripts/deploy.sh        # Deploys to 'production' schema automatically

EMBEDDING_MODEL
  Value: text-embedding-004
  Purpose: Google Gemini model for embeddings
  Required: Only if generating embeddings

OUTPUT_DIMENSIONALITY
  Value: 1536
  Purpose: Embedding vector dimension
  Required: Yes (when using embeddings)

BATCH_SIZE
  Value: 8
  Purpose: Records processed per embedding batch
  Required: No (default: 8)
