▶️  STEP 1.1: PREREQUISITES & SYSTEM REQUIREMENTS
────────────────────────────────────────────────────────────────────────────

Before starting, ensure you have installed:

1. Docker & Docker Compose
   $ docker --version           # Should show: Docker version 20.10+
   $ docker-compose --version   # Should show: Docker Compose version 1.29+

   Installation (if missing):
   Ubuntu/Debian: $ sudo apt-get install docker.io docker-compose
   macOS:         $ brew install docker docker-compose
   Windows:       Download Docker Desktop from docker.com

2. Python 3.9 or higher
   $ python3 --version          # Should show: Python 3.9+ or Python 3.10+

   Installation (if missing):
   Ubuntu/Debian: $ sudo apt-get install python3 python3-pip python3-venv
   macOS:         $ brew install python3
   Windows:       Download from python.org

3. Git (for cloning repository)
   $ git --version              # Should show: git version 2.x+

4. Make (for automation)
   $ make --version             # Should show: GNU Make 4.x+

   Installation (if missing):
   Ubuntu/Debian: $ sudo apt-get install build-essential
   macOS:         Already installed with Xcode Command Line Tools
   Windows:       $ choco install make (via Chocolatey)

5. System Resources (Minimum)
   - RAM: 4 GB available
   - Disk: 5 GB free space
   - CPU: 2 cores or more

TROUBLESHOOTING
════════════════════════════════════════════════════════════════════════════

▶️  ENVIRONMENT VALIDATION ISSUES
────────────────────────────────────────────────────────────────────────────

Problem: "make validate" fails with errors
Solution:
  1. Read error messages carefully
  2. Check which .env file has issues
  3. Fix configuration in that file
  4. Re-run: make validate

Problem: "GOOGLE_API_KEY format may be invalid"
Solution:
  1. Verify API key starts with "AIza"
  2. Get new key from: https://aistudio.google.com/app/apikey
  3. Update all service .env files with same key
  4. Re-run: make validate

Problem: "Services use different database hosts"
Solution:
  All services must use same DATABASE_URL
  Check: mcp_server/.env, client_mcp/.env, email_service/.env, SQL/.env
  Should all have: postgresql://mcp_user:mcp_password@localhost:5434/mcpdb


▶️  DOCKER ISSUES
────────────────────────────────────────────────────────────────────────────

Problem: "Cannot connect to the Docker daemon"
Solution:
  $ sudo systemctl start docker       # Linux
  $ open -a Docker                    # macOS
  Verify: $ docker ps

Problem: "Container 'mcp-postgres' not found"
Solution:
  $ cd DockerConfig
  $ docker-compose up -d postgres
  $ docker ps | grep postgres

Problem: "Port 5434 already in use"
Solution:
  Find conflicting process:
  $ lsof -i :5434
  Kill or change port in DockerConfig/.env

Problem: "PostgreSQL healthcheck failing"
Solution:
  Wait 30-60 seconds for initialization
  Check logs: $ docker logs mcp-postgres
  If errors persist, recreate container:
  $ cd DockerConfig
  $ docker-compose down
  $ docker volume rm dockerconfig_postgres-data
  $ docker-compose up -d


▶️  DATABASE ISSUES
────────────────────────────────────────────────────────────────────────────

Problem: "Schema 'test' does not exist"
Solution:
  Re-run database deployment:
  $ cd SQL
  $ ./scripts/deploy.sh

Problem: "No products found" or "Products loaded: 0"
Solution:
  Re-populate database:
  $ cd SQL/src
  $ python3 populate.py --db --embeddings

Problem: "Extension 'vector' does not exist"
Solution:
  $ docker exec mcp-postgres psql -U mcp_user -d mcpdb \
    -c "CREATE EXTENSION IF NOT EXISTS vector;"
  Then re-run: cd SQL && ./scripts/deploy.sh

Problem: "Google API quota exceeded" during embeddings
Solution:
  1. Reduce batch size in SQL/.env: BATCH_SIZE=4
  2. Use Free Tier API key (15 requests/minute limit)
  3. Wait 24 hours for quota reset
  4. Or upgrade to paid tier


▶️  SERVICE STARTUP ISSUES
────────────────────────────────────────────────────────────────────────────

Problem: "MCP Server fails to start"
Solution:
  1. Check logs: $ tail -f logs/mcp_server.log
  2. Verify port 8009 is free: $ lsof -i :8009
  3. Check mcp_server/.env configuration
  4. Verify database is running
  5. Try manual start:
     $ cd mcp_server
     $ python server.py

Problem: "Odiseo Bot cannot connect to MCP Server"
Solution:
  1. Verify MCP Server is running: $ curl http://localhost:8009/health
  2. Check MCP_HOST and MCP_PORT in client_mcp/.env
  3. Check firewall rules
  4. Restart MCP Server first, then Odiseo Bot

Problem: "ModuleNotFoundError: No module named 'X'"
Solution:
  Activate venv and reinstall dependencies:
  $ source .venv/bin/activate
  $ pip install -r requirements.txt

Problem: "Permission denied" when running scripts
Solution:
  $ chmod +x scripts/*.sh
  $ chmod +x SQL/scripts/*.sh


▶️  TESTING ISSUES
────────────────────────────────────────────────────────────────────────────

Problem: "Tests fail with database connection errors"
Solution:
  1. Ensure PostgreSQL is running
  2. Verify DATABASE_URL in .env files
  3. Check test database is initialized

Problem: "Vector search tests fail"
Solution:
  1. Verify embeddings loaded:
     $ docker exec mcp-postgres psql -U mcp_user -d mcpdb \
       -c "SELECT COUNT(*) FROM test.products WHERE embedding IS NOT NULL;"
  2. If count is 0, reload data with embeddings:
     $ cd SQL/src && python3 populate.py --db --embeddings

Problem: "Coverage too low"
Solution:
  This is a warning, not an error. Tests still passed.
  To improve coverage, add more tests in test/ directory.

  │  - User interaction management                                  │
  └────────────────────────┬────────────────────────────────────────┘
                          │
                          ▼
  ┌─────────────────────────────────────────────────────────────────┐
  │                      APPLICATION LAYER                          │
  ├─────────────────────────────────────────────────────────────────┤
  │  MCP Server (mcp_server)            Agent Service (agent)       │
  │  - FastMCP framework                - Gemini integration        │
  │  - Tool exposure via MCP            - Advanced reasoning        │
  │  - Product search (vector)          - Function calling          │
  │  - Booking management                                           │
  │  - Memory management                                            │
  └────────────────────────┬────────────────────────┬───────────────┘
                          │                        │
                          ▼                        ▼
  ┌─────────────────────────────────────────────────────────────────┐
  │                       WORKER LAYER                              │
  ├─────────────────────────────────────────────────────────────────┤
  │  Email Worker (email_service)                                   │
  │  - Async email queue processing                                 │
  │  - SMTP integration                                             │
  │  - Booking notifications                                        │
  └────────────────────────┬───────────────────────────────────────┘
                          │
                          ▼
  ┌─────────────────────────────────────────────────────────────────┐
  │                         DATA LAYER                              │
  ├─────────────────────────────────────────────────────────────────┤
  │  PostgreSQL + pgvector (mcp-postgres)                           │
  │  - Product catalog (90 items)                                   │
  │  - Vector embeddings (768-dim, Gemini)                          │
  │  - Booking system (appointments, hours, blocks)                 │
  │  - Email queue                                                  │
  │  - Memory system (conversations, agents, users)                 │
  │  - Pagination contexts                                          │
  └─────────────────────────────────────────────────────────────────┘

Ports:
  5434  - PostgreSQL
  8009  - MCP Server (FastMCP)
  8000  - Agent Service
  8090  - pgAdmin (optional UI)

Communication:
  - All services connect to PostgreSQL on localhost:5434
  - Odiseo Bot → MCP Server (HTTP REST API)
  - MCP Server → PostgreSQL (psycopg2)
  - Email Worker → PostgreSQL (queue polling)
  - All services use Google Gemini API for AI capabilities
